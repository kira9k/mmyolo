# Focus + Add без повторного суммирования ветвей C2f

Отдельные конфиги:

- `configs/yolov8/yolov8_n_focus_add_last_spp_concat_surgery2.py`.
- `configs/yolov8/yolov8_s_focus_add_last_spp_concat_surgery2.py`.

Они наследуют соответствующие Focus + Add + SPPF Concat конфиги.
SPPF по-прежнему объединяет четыре ветви через Concat, межмасштабное
объединение neck остаётся Add. Внутри C2f backbone и neck используется
новый режим `csp_fusion_mode='add_last'`. Старые конфиги не меняются.

В обоих конфигах явно указано `spp_fusion_mode='concat'`. Схема SPPF:

```text
x -> pool -> p1 -> pool -> p2 -> pool -> p3
Concat(x, p1, p2, p3) -> conv
```

Здесь один Concat по каналам, без Add между ветвями пулингов. Это отдельное
изменение от удаления повторного суммирования в C2f: Add в C2f и neck
сохраняются там, где нужны для выбранной архитектуры. Совместимость
конкретного графа с ускорителем всё равно необходимо проверить компиляцией.

## Формула C2f

После основной свёртки Split выдаёт `a` и `b`. Обозначим выходы
последовательных bottleneck как `z1 = B1(b)`, `z2 = B2(z1)` и так далее.

```text
Прежний add:  final_conv(a + b + z1 + ... + zn)
Новый режим:  final_conv(a + zn)
```

Все bottleneck выполняются, residual-связи внутри них сохраняются.
Если bottleneck один и residual включён, формула до final_conv меняется
с `a + 2*b + F(b)` на `a + b + F(b)`. Если bottleneck нет, оба режима
возвращают `final_conv(a + b)`.

Для нескольких bottleneck новый режим также не складывает промежуточные
выходы отдельно с финальным. Это не отключение residual-связей: их
вклад внутри последовательной цепочки сохраняется.

Внешнее объединение C2f требует одного Add вместо `num_blocks + 1`.
Обучаемых параметров столько же, сколько в соответствующем прежнем Add
варианте; меняются вычисления и значения признаков. Качество и скорость
на TIDL необходимо сравнивать экспериментально.

## Обучение

Запуск из корня `mmyolo`:

```bash
CONFIG=configs/yolov8/yolov8_s_focus_add_last_spp_concat_surgery2.py
OUT=work_dirs/yolov8_s_focus_add_last_spp_concat_surgery2

python tools/train.py "$CONFIG" \
  --work-dir "$OUT" --model-surgery 2
```

Для nano замените `s` на `n` в CONFIG и OUT. Не используйте каталог
старого эксперимента и его `--resume`: формула сети изменилась.
Конфиги запускают обучение с `load_from=None`, `resume=False`.
Хотя формы весов старого Add совместимы, перенос этих весов не сохраняет
предсказания; такое дообучение следует проводить отдельным экспериментом.

Вход, нормализация и пайплайны наследуются: grayscale 640x640 упаковывается
через внешний Focus4 в `(1,16,160,160)`. Сохраняется одна свёртка перед
первым Split. Используются ReLU, thermal-аугментации наследуются из базы.

## Экспорт ONNX

После обучения укажите checkpoint нового эксперимента:

```bash
CHECKPOINT="$OUT/best_coco_bbox_mAP_epoch_100.pth"

python projects/easydeploy/tools/export_onnx.py "$CONFIG" "$CHECKPOINT" \
  --model-only --model-surgery 2 --img-size 640 640 \
  --opset 11 --device cpu --work-dir "$OUT/onnx"
```

Число эпох в имени checkpoint замените фактическим. Контракт экспорта
не изменяется: вход `(1,16,160,160)`, три объединённых выхода с шагами
8, 16, 32 относительно исходного изображения. Для одного класса формы
выходов `(1,65,80,80)`, `(1,65,40,40)`, `(1,65,20,20)`; сначала cls-logit,
затем 64 канала DFL. Квантование не выполняется.

Для шести пулингов 3 x 3 вместо трёх 5 x 5 добавьте к команде экспорта
`--maxpool-3x3`. Четыре входные ветви единственного Concat при этом
сохраняются: исходный тензор и результаты после второго, четвёртого
и шестого пулингов 3 x 3. Это опция экспорта, не отдельная обучаемая
архитектура; повторное обучение из-за одного разложения пулингов не нужно.

Режим `add_last` поддержан и в перестройке C2f для структурного прунинга;
дальнейший процесс описан в [инструкции по прунингу](yolov8_pruning.md).
