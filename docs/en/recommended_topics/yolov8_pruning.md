# Структурный прунинг YOLOv8 без квантования

Инструмент физически удаляет каналы Conv/BatchNorm через Torch-Pruning.
Обнуление весов, INT8 и PT2E не выполняются. Преобразования surgery,
применявшиеся при обучении, должны сохраняться.
Поддерживаются обычная YOLOv8 и варианты Focus+Add, включая Concat в SPPF.

## Установка

В окружении MMYOLO:

```bash
pip install -r requirements/pruning.txt
```

## Пример для обученной YOLOv8s

Все команды выполняйте в окружении MMYOLO из корня `mmyolo`;
в Docker это обычно `/mmyolo`. Квантование не нужно.
Этот checkpoint обучался с `--model-surgery 2`, поэтому в примере
тот же режим указан при прунинге, дообучении и экспорте.

Прунинг этого checkpoint уже выполнен: если файлы в каталоге `OUT`
существуют, пропустите вызов `prune.py` и переходите к дообучению.
Для нового эксперимента выберите другой `OUT`.

```bash
OUT=work_dirs/yolov8_s_small_dataset_v3_pruned_r20_surgery2

python projects/easydeploy/tools/prune.py \
  work_dirs/yolov8_s_small_dataset_v3/yolov8_s_syncbn_fast_8xb16-500e_coco.py \
  work_dirs/yolov8_s_small_dataset_v3/best_coco_bbox_mAP_epoch_499.pth \
  --prune-ratio 0.2 --round-to 16 --scope backbone-neck --device cpu \
  --model-surgery 2 \
  --output "$OUT/model.pth"
```

Сохраняются три файла:

- `model.pth`: FP32-веса уменьшенной модели и метаданные прунинга.
- `model.py`: исходный конфиг с фактическими размерами уменьшенных слоёв.
- `model.json`: параметры, оценочные MACs, формы выходов и изменённые свёртки.

Исходные веса не изменяются. Старые optimizer/EMA-состояния не копируются,
так как они имеют несовместимые размеры. Перезапись результатов запрещена
без `--force`; исходный checkpoint нельзя перезаписать даже с этим флагом.

Для другого уровня прунинга меняйте и `--prune-ratio`, и каталог `OUT`.
Например, для 10% используйте `--prune-ratio 0.1` и каталог с суффиксом
`_pruned_r10`. Для другой модели замените исходные конфиг и checkpoint.

## Настройки

- `--prune-ratio`: целевая доля удаляемых каналов для групп; по умолчанию 0.2.
  Это не доля удаляемых параметров и не прогноз ускорения.
- `--round-to`: округление оставшихся каналов; по умолчанию 16.
  Округление может увеличить фактическую долю удалённых каналов.
  Число 16 является стартовым вариантом для измерений, не требованием TIDL.
- `--scope backbone`: сокращать backbone; downstream-входы neck
  подстраиваются, но его выходные каналы не сокращаются.
- `--scope backbone-neck`: сокращать backbone и neck; режим по умолчанию.
- `--scope all`: также сокращать внутренние каналы головы.
- `--img-size 640 640`: размер изображения до внешнего Focus.
- `--device cpu` или `--device cuda:0`: устройство анализа и проверки.
- `--model-surgery 2`: воспроизвести режим, использованный при обучении.
  Для модели, обученной без surgery, используйте `--model-surgery 0`.
  Без аргумента режим берётся из `pruning_model_surgery` нового конфига;
  если этой записи нет, используется 0. По исходному checkpoint режим
  автоматически определить нельзя: активации не содержат обученных весов.

Первая свёртка backbone защищена от сокращения выходных каналов.
Конечные cls/DFL-свёртки всегда сохраняют число выходных каналов.
В режиме backbone-neck скрытые выходные каналы головы также сохраняются,
но входы её первых свёрток подстраиваются под уменьшенный neck.
Число классов, reg_max, Add/Concat и внешний Focus не меняются.
При surgery 2 сохраняются фактически обученные ReLU, а не исходные SiLU
из конфигурации до преобразования. Перед прунингом скрипт сравнивает
результаты eager-модели с моделью после настоящего FX surgery 2.
При несовпадении результатов операция останавливается.
В новом конфиге активации записаны явно как ReLU; режим surgery также
сохраняется в конфиге и метаданных checkpoint.

Важно: прежний результат в `yolov8_s_small_dataset_v3_pruned_r20`,
созданный без учёта surgery, восстановлен с неверными SiLU для этих весов.
Для этой модели используйте новый каталог с суффиксом `_surgery2`;
не продолжайте дообучение из старого результата.

C2f временно представляется двумя эквивалентными свёртками при построении
графа зависимостей. После прунинга они объединяются обратно в один Conv
перед исходным Split. В сохранённой модели нет временных ветвей.
Размер `mid_channels` пересчитывается; Add сокращается согласованно.

## Загрузка и дообучение

Используйте **новый конфиг и новые веса вместе**. Старый конфиг не описывает
уменьшенные размеры слоёв. `model.pruning_structure` восстанавливает их
при построении YOLODetector до загрузки checkpoint.

Для проверки загрузки:

```python
from mmdet.apis import init_detector

model = init_detector(
    'work_dirs/yolov8_s_small_dataset_v3_pruned_r20_surgery2/model.py',
    'work_dirs/yolov8_s_small_dataset_v3_pruned_r20_surgery2/model.pth',
    device='cpu')
```

Новый конфиг содержит `load_from` с путём к уменьшенным весам и
`resume=False`. При переносе файлов на другую машину обновите `load_from`.
Исходный конфиг рассчитан на 500 эпох и LR 0.01. Для первого дообучения
предлагается 50 эпох с LR 0.001 и cosine-расписанием. Валидация идёт
каждую эпоху, warmup занимает одну эпоху, а последние 10 эпох проходят
без Mosaic. Это стартовые настройки, а не гарантия восстановления качества.

Не добавляйте `--resume` при первом дообучении: уменьшенные веса загружаются
через `load_from`, а optimizer и EMA создаются заново.

```bash
OUT=work_dirs/yolov8_s_small_dataset_v3_pruned_r20_surgery2

python tools/train.py "$OUT/model.py" \
  --work-dir "$OUT/finetune" \
  --model-surgery 2 \
  --cfg-options \
  train_cfg.max_epochs=50 \
  train_cfg.val_interval=1 \
  'train_cfg.dynamic_intervals=[]' \
  optim_wrapper.optimizer.lr=0.001 \
  default_hooks.param_scheduler.max_epochs=50 \
  default_hooks.param_scheduler.scheduler_type=cosine \
  default_hooks.param_scheduler.lr_factor=0.1 \
  default_hooks.param_scheduler.warmup_epochs=1 \
  default_hooks.param_scheduler.warmup_mim_iter=0 \
  default_hooks.param_scheduler.warmup_bias_lr=0.001 \
  custom_hooks.1.switch_epoch=40
```

Если выбрали другой каталог результатов, задайте его в `OUT`.
Аргумент `custom_hooks.1.switch_epoch` подходит к конфигу этого примера:
второй custom hook — `mmdet.PipelineSwitchHook`. У другой модели сначала
проверьте порядок hooks. Недостаточно менять только верхнеуровневые
`max_epochs` и `base_lr`: сохранённый конфиг уже содержит готовые значения
внутри `train_cfg`, optimizer и scheduler.

Скрипт не дообучает модель автоматически. В этом примере сохраняется
обученная RGB/ReLU-архитектура после surgery 2. Для модели, обученной
без surgery, не добавляйте этот флаг при дообучении и экспорте.

## Экспорт дообученной модели в ONNX

После успешного дообучения выбирайте лучшие веса по `bbox_mAP`, а не
исходный checkpoint до прунинга или до дообучения:

```bash
OUT=work_dirs/yolov8_s_small_dataset_v3_pruned_r20_surgery2

CHECKPOINT=$(find "$OUT/finetune" -maxdepth 1 \
  -name 'best_coco_bbox_mAP_epoch_*.pth' | sort -V | tail -n 1)

python projects/easydeploy/tools/export_onnx.py \
  "$OUT/model.py" "$CHECKPOINT" \
  --model-only --model-surgery 2 --raw-output-format combined \
  --img-size 640 640 --batch-size 1 \
  --opset 11 --device cpu \
  --work-dir "$OUT/onnx"
```

Если `CHECKPOINT` пуст, проверьте наличие файла лучших весов в `finetune`.
Можно назначить путь явно: `CHECKPOINT="$OUT/finetune/best_coco_bbox_mAP_epoch_XX.pth"`,
заменив `XX` фактическим номером эпохи.

Результат сохраняется в `$OUT/onnx` с именем выбранного checkpoint и
расширением `.onnx`. Это FP32-экспорт без INT8-калибровки, декодера и NMS.
Для RGB-модели этого примера вход имеет форму `(1,3,640,640)`, а три
объединённых выхода — `(1,65,80,80)`, `(1,65,40,40)`, `(1,65,20,20)`.
Порядок каналов: один cls-logit, затем 64 канала DFL.

Всегда используйте новый `$OUT/model.py`: исходный конфиг не описывает
уменьшенные слои. Для Focus-вариантов та же команда с `--img-size 640 640`
задаёт размер до Focus; экспортёр берёт размеры упакованного входа из
`deploy_cfg.input_spatial_divisor`.

## Проверки

Перед сохранением выполняется forward с исходными размерами входа,
проверяются конечность значений и неизменность форм выходов, затем
создаётся новая модель из сохранённой структуры и проверяется точное
совпадение её результатов с уменьшенной моделью.

Тесты покрывают RGB, Focus n/s, Add/Concat в SPPF, области прунинга,
сохранение/загрузку, шаг обучения и FP32 ONNX с ONNX Runtime.
Отдельный тест проверяет surgery 2: ReLU в сохранённом конфиге,
согласованность после повторного FX-преобразования при дообучении
и экспорт с `--model-surgery 2`.
Без Torch-Pruning структурные тесты пропускаются.

Прунинг обычно снижает качество до дообучения. MACs и число параметров
не заменяют измерение задержки на TIDL. Прежде чем выбирать вариант,
сравните mAP/recall и послойный профиль на целевом устройстве.
